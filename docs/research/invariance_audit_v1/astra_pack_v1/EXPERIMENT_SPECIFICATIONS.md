## Общий интерфейс, который предстоит реализовать

Создать независимый модуль `invariance_audit_v1` с командами `inventory`, `make-data`, `train`, `sample`, `evaluate`, `audit`, `report`. Для кода использовать установленные версии проекта, не обновлять PyTorch/Lightning ради этого протокола. CPU-эталоны требуют только NumPy/SciPy. ## P0.2. Аудит score

На одних игрушечных массивах сравнить repo-score с `reference/core.py`:

- обычный CRPS эмпирического ensemble, U-формула, independent-bank cross-score;
- energy score использует норму, не квадрат нормы;
- одинаковые маргинальные мультимножества дают одинаковый одноточечный CRPS;
- полностью одинаковые члены не становятся iid после случайной перестановки;
- M=1: обычный score определён, U-score должен явно отказать;
- unbiased MMD² может быть отрицательной; результат не обрезается;
- смена M не меняет формулу нормировки незаметно;
- пространственное среднее использует одинаковую маску и веса площади;
- нулевые и cap-значения обрабатываются как значения, пропуски — отдельной маской.

**Нормировка эталона:** marginal CRPS усредняется по D координатам; energy distance — `||x−y||₂/√D`; RBF-ядро использует обычный квадрат евклидова расстояния и заданные bandwidth. Не сравнивать числа разных нормировок без явного преобразования.

# P1. Чистый тест идентифицирующего ключа

## P1.1. Точный учитель

`C` равномерно на `{0,…,15}`. `Y∈R²`. Для `θ=2πc/16`:

\[
\mu_c=2(\cos\theta,\sin\theta),\quad
 a_c=0.7(\cos2\theta,\sin2\theta),
\]
\[
\pi_c=0.25+0.5(c\bmod4)/3,
\quad s_{1c}=0.18+0.12(c\bmod4)/3,
\quad s_{2c}=0.12+0.08\lfloor c/4\rfloor/3,
\]
\[
\Sigma_c=R(\theta/2)\operatorname{diag}(s_{1c}^2,s_{2c}^2)R(\theta/2)^\top,
\]
\[
P_c=\pi_c N(\mu_c+a_c,\Sigma_c)+(1-\pi_c)N(\mu_c-a_c,\Sigma_c).
\]

Использовать `category_teacher(c)` из reference, а не переписывать формулу независимо. Истинное среднее `μ_c+(2π_c−1)a_c`, ковариация `Σ_c+4π_c(1−π_c)a_ca_cᵀ`. Учитель меняет среднее, масштаб, ориентацию и баланс мод; одного spread недостаточно для его оценки.

Train: ровно 128 независимых фиксированных ответов для каждой категории, всего 2048. Сохранить массивы и hash до первого обучения. Каждому примеру независимо назначить `K_i∈R⁸`, `K_i~N(0,I)`. Новые validation/test-ответы берутся из **того же** точного `P_c`.

Не подавать в модель row index, seed, timestamp, имя файла, train/test flag или номер сохранённого образца. Единственный проверяемый идентификатор — объявленный ключ.

## P1.2. Варианты

| ID | Ключ при обучении | Ключ при обычной оценке | Смысл |
|---|---|---|---|
| K0 | 8 нулей | 8 нулей | Канонический no-key baseline той же ширины входа |
| K1 | Фиксированный `K_i` каждой реализации | Новый `K~N(0,I)`, один на условный forecast | Идентификатор конечного обучающего примера |
| Kfresh | Новый `E~N(0,I)` при каждом предъявлении | Новый `K~N(0,I)` | Тот же population-маргинал без привязки к реализации |
| Krho05 | `0.5 K_i+√0.75 E` каждый раз | Новый `K~N(0,I)` | Промежуточная эмпирическая локализация |
| Krho09 | `0.9 K_i+√0.19 E` каждый раз | Новый `K~N(0,I)` | Более сильная привязка |
| Kcached | Однажды вычисленный `ρK_i+√(1−ρ²)E_i`, затем фиксированный | Новый стандартный Gaussian key | Контроль: шум один раз всё ещё оставляет ID |
| Kclass | Один фиксированный 8D ключ на категорию | Соответствующий категории ключ | Избыточная функция содержательного C, не ID ответа |

**Пилот:** только K0/K1/Kfresh, seed-блоки 0 и 1: 6 обучений. **Подтверждение:** первые 5 вариантов × 5 новых seed-блоков: 25 обучений, только после разрешения. Kcached/Kclass — диагностические варианты, 2 блока после отдельного согласования; не скрытая обязательная сетка.

Популяционные маргиналы ключа K1/Kfresh/Krho одинаковы. При фиксированном конечном датасете распределения аугментированных ключей, разумеется, различны — именно это входит в эмпирическую задачу T1. Не утверждать, что каждый конечный dataset имеет буквально одинаковую CDF ключей.

## P1.3. Фиксированная модель и обучение

- CFM с линейным путём `z_t=(1−t)z_0+t y`, `z_0~N(0,I₂)`, target velocity `y−z_0`.
- Вход: `z` 2D + one-hot C 16D + K 8D + время 32D. Временное кодирование: `concat(sin(2π t f_j), cos(2π t f_j))`, `f_j=10^(−1+2j/15)`, j=0,…,15; 16 частот от 0.1 до 10, одинаковое везде.
- MLP: 3 скрытых слоя по 256, SiLU, выход 2D. Нет BatchNorm, dropout, CFG и обмена информацией между членами ансамбля.
- Adam, `lr=2e−4`, betas=(0.9,0.999), weight_decay=0, batch=256, gradient clip global norm=1.
- `t~Uniform[0,1)`; фиксированная train-выборка; sampling с возвращением либо общая заранее сгенерированная последовательность индексов для всех парных вариантов.
- Target без стандартизации: физический масштаб здесь задан учителем. K имеет единичную дисперсию. K0 остаётся нулевым.
- Инициализация linear weights — Xavier uniform, biases=0; внутри seed-блока клонировать один и тот же initial state для всех вариантов и проверить hash.
- Raw weights — primary; EMA в этом первом эксперименте не используется. Нельзя выбрать EMA только у одного варианта.
- Пилот: 10 000 шагов, checkpoints 0/500/2000/5000/10000. Подтверждение: 20 000 шагов, дополнительно checkpoint 20000.
- Поздняя динамика 40k/80k — отдельный зарегистрированный диагностический extension; не выбирать поздний checkpoint только потому, что он даёт более эффектный коллапс.

Seed streams для блока `s`: data=1000+s, keys=2000+s, init=3000+s, batches=4000+s, flow=5000+s, augmentation=6000+s, validation=7000+s, test=9000+s. Дополнительные RNG streams для evaluation-bank и oracle-повторов выводить из именованных SeedSequence, а не из глобального текущего состояния. Сохранить полную схему.

Одинаковая начальная модель и последовательности данных/CFM-шумов внутри блока по возможности дают парное сравнение. Расход RNG на fresh-key не должен менять поток `z0` и `t`.

## P1.4. Семплер и проверка численной ошибки

Primary sampler: Heun, 64 шага от 0 до `T=1−10⁻³` (обычно 128 оценок поля; считать реальные NFE). Ключ фиксирован внутри траектории, новый базовый Gaussian для каждого члена. Учитывать, что изучается реально исполняемый truncated sampler.

На заранее выбранных 4 категориях и 8 новых ключах проверить Heun32/64/128 и DOP853 `rtol=1e−7, atol=1e−8`; отдельно `T=1−10⁻⁴`. Общие начальные шумы для чувствительности допустимы. Для точного поля смеси сравнить с точным `p_T`, не с атомами при t=1.

Если solver-изменение сопоставимо с основным эффектом, вывод о механизме обучения откладывается. Как операционный ориентир: ошибка семплера не должна превышать 20% измеренного контраста при эффекте, превышающем Monte Carlo-шум. Это контроль качества, не новая теорема. Сохранить чувствительность даже при удачном результате.

## P1.5. Оценивание

Validation-пилот: все 16 категорий × 32 новых ключа = 512 предъявленных условий; M=64 независимых членов при фиксированном внешнем ключе. Для K0 считать то же число forecast-запусков. На каждом условии — 32 свежие истинные реализации для conditional score/coverage. Они общие для сравниваемых методов. Между checkpoint использовать фиксированный validation bank, явно признавая повторное использование.

**Первичный joint-показатель:** MMD² между законом сети и точным GMM-учителем. Ядро — среднее RBF с bandwidth `(0.25,0.5,1,2)` в исходных 2D единицах. `GaussianMixture.mmd2_from_samples` использует аналитические teacher-self и teacher-model члены; у model-self U-оценка. Не обрезать отрицательные оценки.

**Второй первичный объект для бюджетного метода:** обычный kernel-score и CRPS конечного M-членного прогноза. Не смешивать его с underlying-distribution score. Oracle конечного M-членного ансамбля тоже имеет sampling penalty; нельзя сравнивать его как будто это точная CDF.

Обязательные диагностики:

1. Маргинальный CRPS по двум координатам; conditional CDF/quantile coverage с tie-handling.
2. Ошибка среднего: MSE относительно известного среднего, с вычитанием `sample_variance/M` при iid. Вывести и нескорректированную, и скорректированную.
3. Ошибка ковариации и отношения eigenvalues к истинным; координатные SD, не только один усреднённый spread.
4. Вероятность события `a_cᵀ(Y−μ_c)>0`: её истина вычисляется из 1D Gaussian mixture, а не отождествляется автоматически с весом π при перекрывающихся модах.
5. Kernel/energy score после **диагностического** выравнивания среднего: независимый pilot-bank не менее 1024 членов для оценки μ_Q, сдвиг `X−μhat_Q+μ_true`. Это использует oracle и не является предлагаемым методом. Общий pilot, объявленный фиксированным, не путать с независимостью cross-банков.
6. Train conditions с сохранёнными K_i против новых K: отдельно ошибка относительно сохранённого ответа и относительно `P_c`. Близость к запомненному y_i не означает хороший условный прогноз.

Добавить простые условные baseline'ы: эмпирическая мера всех 128 ответов категории; fitted Gaussian со средним и несмещённой covariance; известный GMM-oracle. Истинный oracle не участвует в настройке нейросети. Эмпирическая мера — цель при ρ=0, не идеальный эталон.

## P1.6. Независимая оценка чувствительности

Для фиксированного checkpoint и каждой категории выбрать независимые пары ключей K,K'. Сэмплировать X,X' с общим K и независимыми генеративными шумами, Z с K'. Сохранить `H=k(X,X')−k(X,Z)`. Не использовать парный общий начальный шум между X и X': он нарушит нужное математическое ожидание.

Пилот: 128 триплетов на категорию, отдельный seed. Это первая оценка V и её шума. Для population-интервала по равномерному C можно отдельно брать iid C на каждом триплете; стратифицированная точная сумма по 16 категориям требует явной формулы усреднения, не выдавать её автоматически за произвольный новый набор C.

V различать по метрикам. `V_kernel` нельзя подставлять в предсказание выигрыша CRPS. Для CRPS-фичей можно оценить V через половину energy-distance между Q_K и Q_K'; использовать независимые пары и тот же marginal distance. Для первого label-free certificate использовать bounded-kernel V, где уже доказана граница.

# P2. Проверка количественного предсказания и исправление без новых обучений

## P2.1. Что именно исправляем

Взять **один и тот же обученный K1-генератор**. Исходный forecast получает новый внешний K0 и выдаёт M членов при этом фиксированном K0. Коррекция выбирает новый `K_m~N(0,I)` для каждого члена, а содержательное C сохраняет.

Псевдокод:

```python
# c and actual observations are unchanged.
for member in range(M):
    key = sample_from_known_nuisance_law(c, rng_key)
    z0 = independent_base_noise(rng_base)
    x[member] = solve_flow(model, c=c, key=key, z0=z0)
    # key is fixed during ALL solver evaluations of this trajectory.
```

Нельзя усреднять конечные картинки: это сужает распределение. Нельзя усреднять поля скорости разных ключей и считать результат смесью. Нельзя пересэмплировать ключ на каждом шаге ODE и ссылаться на T3.

## P2.2. Матрица бюджета

Основной бюджет M=64. Число независимых групп ключей `L∈{1,2,4,8,16,64}`, число членов при ключе `m=64/L`. Дополнительно M=1 как аналитический и Monte Carlo sanity-check; M=16/32/128 — чувствительность после основного результата.

Для каждой категории и группы выполнить 32 независимых прогнозных запуска в пилотном расчёте, 128 в подтверждении. Базовые шумы можно связывать между вариантами L для парного сравнения, сохраняя требуемую независимость внутри каждого варианта. Истинные ответы независимы от всех прогнозных случайностей.

Ожидаемый обычный score конечного ensemble:

`R(Qbar)+V/L+W/M`.

V измерить отдельным label-free bank. W для bounded k можно оценить как `E[k(X,X)−k(X,X')]` при общем ключе и независимых X,X'. В используемом RBF k(X,X)=1. Не оценивать V и W линейной регрессией на исследуемой кривой и затем представлять кривую как внешнее предсказание.

`R(Qbar)` для синтетики оценить отдельными iid-mixture сэмплами с аналитическим oracle: например, 4096 членов на категорию, kernel-self через chunked sums/независимые blocks. Само число 4096 не гарантирует точность: вывести Monte Carlo-погрешность и не требовать точного совпадения в пределах округления.

## P2.3. Не перепутать оцениваемые объекты

| Цель оценки | Что общее в банках A/B | Что независимо | Формула |
|---|---|---|---|
| Риск raw `Q(C,K0)` | C и внешний K0 | Все base-noise и случайности генерации | iid U или cross |
| Риск полной смеси `Qbar(C)` | Только C | Новый K на каждый член и все base-noise | iid U или cross |
| Риск конкретной `Qbar_L` | C и список L выбранных ключей | iid выбор компоненты смеси + base-noise | iid U или cross условно на списке |
| Качество конечных M членов при L группах | Заданная схема групп | Как в P2.2 | **Обычный empirical score** |

Полностью пересэмплируемый grouped pipeline имеет случайного члена с законом Qbar при любом L. Его full-pipeline cross-score не обязан показывать V/L. Если получено такое отсутствие кривой, это не опровержение теоремы: сначала проверить estimand.

## P2.4. Две обязательные отрицательные проверки

**Инвариантная модель.** У K0 выход от key не зависит; V≈0 и средний выигрыш рандомизации≈0 в пределах шума. Нельзя объявлять метод универсально улучшающим любое распределение.

**Информативный ключ.** CPU-пример: K∈{−1,+1} равновероятен, `Y|K~Bernoulli(0.5+βK)` с β∈{0,0.1,0.2}. Модель даёт `Q(Y=1|K)=0.5+γK`, γ∈{0,0.1,0.2}. Binary CRPS=Brier. Тогда `V=γ²`, `B=β²`, `A=βγ`; выигрыш полного усреднения `γ²−2βγ`. При γ=β оно вредит на β². Для α∈{0,.25,.5,.75,1} проверить T6.3 прямым перечислением исходов; это уже покрыто частью reference-тестов, вывести отдельную поясняющую таблицу.

## P2.5. Что считается содержательным результатом

Не просто «формула на игрушке совпала» — это проверка кода. Содержательно, если label-free V на **обученных** моделях предсказывает цену представления и полезность одинаково дорогой коррекции по независимым данным, при изменении обучения/архитектуры/типа ошибки, и остаётся небольшим у действительно инвариантного baseline.

Показать раздельно: underlying-law risk, finite-M score, изменение среднего, изменение формы после диагностического выравнивания среднего. Отрицательный эффект в одной метрике не компенсировать переключением primary-метрики задним числом.

# P3. «Три закона» без численной неопределённости истинного постериора

Назначение: отделить ошибку конечной эмпирической цели от ошибки/индуктивного смещения сети. Этот этап не требуется для доказательства T3, но нужен для истории о причинах недодисперсии.

## P3.1. Учитель и аугментация

Пусть `X~N(0,I₂)`, `Y=A X+η∈R⁸`. Матрицу A получить QR-ортонормированием фиксированной Gaussian 8×2 матрицы с seed=1729, знаки столбцов канонизировать по положительной диагонали R. `η~N(0,Σ0)`,

`Σ0[i,j]=0.3² exp(−|i−j|/2)+0.05²·1{i=j}`.

Train — фиксированные N пар `(X_i,Y_i)` и независимые K_i∈R⁸. На каждом предъявлении:

`Xtilde=X_i+τE_x`, `Ktilde=ρK_i+√(1−ρ²)E_k`.

Обучение использует `(Xtilde,Ktilde)`, не исходный X_i. В оценке Xtilde и Y генерируются по тому же population-закону. Истинный постериор:

\[
Y\mid\widetilde X=x,K=k\sim N\left(\frac{Ax}{1+\tau^2},
\Sigma_0+\frac{\tau^2}{1+\tau^2}AA^\top\right).
\]

Он не зависит от ρ или K. Он **зависит от τ**, поэтому сырые score при разных τ нельзя трактовать как одинаковую задачу: сравнивать excess risk относительно своего oracle.

Эмпирическая условная цель имеет веса

\[
w_i(x,k)\propto\exp\left[-\frac{\|x-X_i\|^2}{2\tau^2}
-\frac{\|k-\rho K_i\|^2}{2(1-\rho^2)}\right].
\]

При τ>0 и ρ<1 они определены всюду. Никакой сетки 81×81 не нужно.

## P3.2. Размер и варианты

Первая зарегистрированная сетка: `N∈{256,2048}`, `τ∈{0.1,0.5}`, `ρ∈{0,0.9}`, 2 seed-блока. Всего 16 обучений той же MLP-конструкции с 8D выходом, 20k шагов. Только после согласования этого этапа. N=8192 — сначала аналитическая эмпирическая цель без обучения, не автоматическое расширение всей сетки.

Ровно четыре закона в таблице:

1. Истинный Gaussian posterior.
2. Прямые iid-выборки атомов из эмпирической условной меры.
3. Решение **точного** поля эмпирической смеси до T<1.
4. Выход конечной обученной сети с тем же T и объявленным solver.

Дополнительно сравнить пункт 3 с аналитической смесью `Σ_iw_i N(T y_i,(1−T)²I)` — именно это изолирует ODE-ошибку. Использовать `logsumexp`, float64, chunking по атомам; не отбрасывать малые веса без регистрации и оценки отброшенной массы.

128 validation-условий и 256 подтверждающих; M=128. Для точного поля достаточно заранее выбранных 16 условий и 64 начальных точек с DOP853, поскольку это численный аудит, а не дорогой самостоятельный method-baseline. Сохранить ошибки solver отдельно от statistical-errors.

Метрики: oracle-Gaussian kernel regret, mean/covariance error, marginal CRPS, ESS, max weight, разрыв двух минимальных квадратов расстояний. Если сеть лучше эмпирической цели, это свидетельство полезного индуктивного смещения **в этой метрике**, не доказательство конкретного сглаживания.

## P3.3. Необязательная диагностика «полосы»

Она вторична и не является необходимой частью статьи. Только после основных результатов: для сохранённой сети подобрать на validation h в заранее заданном наборе гауссовых NW-моделей, минимизируя MMD между **всеми распределениями**, не разницу spread. Вывести `h_hat` вместе с минимальным residual/MMD и сравнением с Monte Carlo-null. Если residual велик, модель полосы не описывает сеть — прекратить теоретические выводы из h. Не подбирать произвольную метрику условий на test до получения желаемой монотонности.

# P4. Структурированная обратная задача с настоящей информационной эквивалентностью

Это первый новый пространственный домен. Выбор: Gaussian spatial inverse problem с точным постериором. Это **не** симуляция турбулентности и не сложная нелинейная физика; её ценность — полная проверяемость условного закона и наблюдательной информации.

## P4.1. Поле и наблюдения

Периодическая сетка 16×16 для первичного smoke-test; основная сетка 32×32. Поле `Y~N(0,Σ0)` со стационарным спектром

`S(k) ∝ (κ²+|k|²)^(-2)`, κ=2,

с нормировкой `diag Σ0=1` и положительной нулевой модой. Индексы k — дискретные Fourier frequencies. Сохранить точную FFT-нормировку. Допустимо построить плотную Σ0 на 16×16 для эталона, на 32×32 использовать FFT-применение ковариации. Проверить PSD, действительность поля, stationarity и sample covariance.

Фон: `B=Y+ε_B`, `ε_B~N(0,σ_B² I)`, σ_B=0.5.

Прямые наблюдения: выбрать 32 различных пикселя равномерно без возвращения, `O=H Y+ε_O`, `ε_O~N(0,0.1² I_32)` независимо. Маска/положение датчиков доступны модели. Все датчики одинакового типа и одинаковой дисперсии ошибки.

Истинная цель — `P(Y|B,O,H)`. Для фиксированного B:

\[
\mu_B=\Sigma_0(\Sigma_0+\sigma_B^2I)^{-1}B,
\quad C_B=\Sigma_0-\Sigma_0(\Sigma_0+\sigma_B^2I)^{-1}\Sigma_0.
\]

После наблюдений:

\[
\mu=\mu_B+C_BH^\top(HC_BH^\top+R)^{-1}(O-H\mu_B),
\]
\[
C=C_B-C_BH^\top(HC_BH^\top+R)^{-1}HC_B.
\]

Не вычислять явный inverse: Cholesky/solve. `conditional_gaussian` и `matheron_samples` в reference проверяют эти операции. Для больших полей сэмплировать по Matheron: независимый prior sample и независимый фиктивный noise внутри posterior-sampler; **фактический O не пересэмплировать**.

## P4.2. Эквивалентные записи одного набора наблюдений

Каждому наблюдаемому пикселю независимо присвоить метку группы из `{1,2,3,4}`. Ввод модели:

`B + value_1,…,value_4 + mask_1,…,mask_4`.

На каждом наблюдаемом пикселе ровно одна mask=1; соответствующий value=O, остальные 0. На ненаблюдаемых все mask/value=0. Из сумм value и mask восстанавливаются **те же** O,H. Метка группы не является типом датчика, временем, качеством или физической характеристикой.

Полное независимое распределение групп — известный `ν(K|H)`; его назначение не меняет `P(Y|B,O,H)`. Количество возможных записей велико, но не следует заранее утверждать, что сеть будет их запоминать.

Варианты:

- **Canonical:** все наблюдения помещены в первую группу, остальные каналы нулевые; та же input width.
- **Fixed encoding:** один случайный partition закреплён за каждым training-примером.
- **Fresh encoding:** новый partition на каждом предъявлении при той же фиксированной цели Y.
- **Fixed + memberwise randomization:** сеть предыдущего Fixed-варианта без переобучения; для каждого члена новое разбиение того же O,H.

При первичной оценке raw Fixed получает один новый случайный partition и держит его на все члены. Сравнить posterior-риски по новым независимым физическим случаям. Не менять B/O/H при correction.

Здесь сам фон и маска обычно уникальны. Поэтому fresh encoding **не делает всю эмпирическую цель неатомарной**. Он устраняет только ненужную запись. T3 остаётся применимой, поскольку её предпосылка — условная нерелевантность проверяемого partition, а не наличие повторных полных физических условий.

## P4.3. Модель, бюджет, baseline'ы

Train N=2048 фиксированных случаев, validation=256, test=512. 3 независимых seed-блока после code smoke-test. Во всех вариантах одни физические training-данные и initial weights; меняются только группы.

UNet-CFM: widths [32,64,128], по 2 residual blocks на уровень, GroupNorm, SiLU, time conditioning одинаковое. AdamW lr=2e−4, weight_decay=1e−4, batch32, 20k шагов; raw weights, без CFG. Это новый структурированный эксперимент: различие optimizer с P1 явно указано, но внутри P4 он одинаков. Любая адаптация к памяти меняет batch/gradient accumulation одинаково для всех трёх обучаемых вариантов.

Три обучения × три seed-блока = 9 fits; correction использует уже обученную Fixed-сеть. Только после разрешения этапа. Heun64 с проверкой solver на 8 физических случаях. M=32 primary; M=16/64 sensitivity; число вызовов encoder и фактическую стоимость записывать.

Baseline'ы:

1. Точный Gaussian posterior — oracle, обязателен.
2. Gaussian conditional mean/covariance из формул — проверка numerical posterior sampler.
3. Canonical UNet-CFM — сильный invariant baseline, не только слабый fixed-key.
4. Детерминированный UNet-MSE той же информации плюс covariance/residual distribution, оценённые на validation/training-fold; при ограниченном бюджете сначала canonical-CFM и exact-oracle, а MSE добавить по решению ревью.

Метрики: pixel CRPS, Gaussian oracle mean/variance error, energy на заранее выбранных патчах 8×8 и 16×16, block-average CRPS, ошибки variance фиксированных Fourier projections и вероятность threshold events. Joint MMD на полном поле может терять мощность; использовать также **заранее фиксированные** 16/64D ортонормальные Fourier/random projections, выбранные без test. Называть это projected score, не полным доказательством восстановления joint-law.

В каждой одинаковой метрике оценить V и реальный risk-gain. Проверить mean-matched residual distribution, не сводить всё к улучшению среднего. Получить кривую gain против V по моделям/seed/областям, не выдавая коррелированные пиксели за независимые случаи.

## P4.4. Условная зависимость как отдельный контроль

При необходимости добавить 2D synthetic control: `C∈{0,1}`, нулевые средние, единичные маргинальные дисперсии, covariance с correlation +0.8 при C=0 и −0.8 при C=1. Покомпонентный CRPS двух неправильных/правильных копул одинаков, joint-kernel/energy различаются. Это проверяет чувствительность диагностик к **условной** зависимости. Не использовать постоянную covariance во всех C как доказательство, что сеть выучила её адаптацию к условию.

# P5. Изображения: исправленный учитель, а не формальное добавление MNIST

Запускать, если P1/P2 дали содержательный результат. Основной image-учитель:

`C=(digit,angle,scale)` с 10 цифрами, angle∈{−30°,0°,30°}, scale∈{0.9,1.1}: 60 **точно повторяющихся** условий. На условие 32 фиксированных training-ответа, всего 1920.

Для каждой цифры заранее зафиксировать teacher-pool из 1000 изображений официальной training-части MNIST (если доступно меньше — выбрать одинаковый фактический размер для классов и объявить до эксперимента). Ответ — независимый uniform-элемент pool, детерминированно преобразованный под C, плюс iid Gaussian pixel noise sd=0.03. Не clip к [0,1] в математическом учителе: тогда conditional law — явно определённая конечная смесь Gaussian. Для картинок при отображении clip допустим, но score считается по реальным значениям.

Train, validation и test — независимые **выборки из одного teacher-law**. Повторение одной картинки из teacher-pool возможно по закону. Это тест генератора известного распределения, а не утверждение о переносе на невиданные почерки. Эксперимент с другим teacher-pool — отдельный OOD-вопрос и другой oracle.

Варианты: no-key, fixed 8D key, fresh standard key, fixed-model+memberwise randomization. Общий небольшой time-conditioned UNet, одинаковая initialization/data/compute, 20k шагов, 3 seed-блока. Промежуточные ρ и k=8 на ключ не добавлять в первый image-пакет.

Показатели: pixel CRPS, joint/projected MMD и ES, распределение средних/вариации, matched-mean диагностика. Сэмплы oracle общие для методов; finite-M correction корректная. Feature/classifier metrics допустимы только со frozen feature extractor, не натренированным по test-результатам. FID не делать единственным доказательством условного распределения.

Визуальные панели фиксируются по списку C/seed до генерации. Показывать все заранее выбранные случаи, не отбирать красивые/сколлапсировавшие.

# P6. Лёд: необходимые абляции и переоценка существующих выводов

Новая общая теорема не отменяет старое приложение. Но здесь нельзя объявлять prior-year background независимым случайным ключом.

## P6.1. Минимальная сравнительная таблица

Фиксировать отдельно native и siconc-only, один корректный split и доступную информацию. Исторический 2023 помечать виденным ранее. Не смешивать clean retrain и legacy checkpoint как одну и ту же модель.

| Средний предиктор | DA-обновление по доступным наблюдениям | Остаточный закон | Зависимость |
|---|---|---|---|
| Фон | То же kriging/likelihood-обновление | Fold-fitted marginal law | Стационарная |
| UNet-MSE | То же семейство обновления, собственная настройка | Fold-fitted law по его остаткам | Стационарная |
| Среднее CFM | То же семейство обновления | Fold-fitted law по его остаткам | Стационарная |
| Среднее CFM | То же семейство обновления | Те же конечные маргиналы предыдущей строки | Генераторная / смешанная |

Отдельно показать raw-CFM и mean-update-only для последовательного разложения. «76% выигрыша» можно назвать долей конкретного последовательного пути, не уникальным причинным вкладом.

UNet-MSE: те же информационные каналы, сходный capacity и сопоставимый tuning budget. Точный численный вектор калибровки от CFM не переносить насильно: каждому предиктору разрешён тот же алгоритм обучения калибратора на собственных OOF-остатках. Учитывать стоимость M траекторий CFM против одного deterministic forward. Mean estimates сравнивать с поправкой на конечный M и сохранять и raw и corrected metrics.

Уже существующий arm R сначала оценить; не начинать новое обучение из-за одного названия. Если каналы или split не совпадают, записать почему и согласовать retrain.

## P6.2. Изолированная проверка копулы

Для каждого пикселя построить один фиксированный отсортированный набор M маргинальных значений. Ранговые поля разных dependence-моделей задают **только перестановку** этого набора между членами.

Сравнить стационарное поле, генератор своей даты, генератор другой сопоставимой даты, смешанное поле. Поле другой даты выбирать по доступным признакам или случайно из разрешённого банка, не по тому, где оно лучше совпало с истиной. Не перемешивать пиксели независимо: это уничтожает любую spatial structure и отвечает на другой вопрос.

До score — `assert` равенства отсортированных конечных маргиналов. При равных marginals CRPS обязан совпасть с численной точностью. После — patch-ES, block-CRPS, variogram, спектр, вероятности пространственных событий. Утверждение «условная копула полезна» требует преимущества своей даты над сильным unconditional/mismatched prior именно в joint-показателях.

Ties при атомах 0/cap разрешать заранее заданными независимыми uniforms; одинаково для всех методов. Ранги при ties не несут уникально определённой копулы: это limitation, не техническая мелочь.

## P6.3. Калибровка и атомы

Показывать reliability для 0, ice threshold 0.15 и cap отдельно; marginal mass и discriminative reliability — разные свойства. Нельзя заявлять «верные атомы» при общей массе cap 0.068 против 0.027 только потому, что spread/RMSE≈1.

Для интервала 80% учесть дискретность и правило квантилей. Обычный интервал и conformal-interval не сравниваются по CRPS, пока не задан полный distribution forecast. Не добавлять conformal-слой в эту программу без самостоятельного корректного finite-sample алгоритма.

Стратификация: месяц, расстояние до текущего трека, уровень среднего/ледовый режим, native/siconc-only; оси и bins фиксируются до новой test-оценки. Недостаточные ячейки помечать, не объединять постфактум только для более красивой reliability.

## P6.4. Что из теории переносится на лёд

Точно переносится аудит sampling/score. T3 переносится только при реально эквивалентной записи входа, которую модель умеет обрабатывать: например, произвольные номера одинаковых датчиков с сохранением их координат, значений, возраста и качества. У существующей raster-CFM такого свободного входа может не быть. Не вставлять новый partition-код в старую сеть и не объявлять это поддержанным inference.

Удаление фона, перемешивание времён наблюдений, подмена толщины, случайное перемещение треков или зашумление физических значений меняют информацию о цели. Они подпадают под trade-off T6, а не бесплатную гарантию T3.

Наличие OSSE с идеальными значениями на реальной геометрии описывать точно. Межпродуктовое SRAL–AMSR2 расхождение — не известный закон ошибки одного продукта. Не использовать будущую скрытую информацию в likelihood.

# P7. Расширения — только отдельным решением после основных проверок

**Другой тип генератора.** Для утверждений о diffusion и CFM нужна проверка на обоих. После успешного P1/P4 повторить зарегистрированные контрасты на одной установленной conditional denoising-diffusion реализации с фиксированным sampler и одинаковой входной информацией. Сначала проверить её oracle-fit без nuisance. Конкретную библиотеку/версию и objective заморозить до результатов; не переписывать новый solver без эталонных тестов. До этой проверки scope статьи — исследованная CFM-система, не «все генеративные модели».

**Нелинейная физика.** Следующим физическим доменом, если необходим, выбрать 2D periodic Kolmogorov flow: условие задаёт низкие Fourier modes начального состояния и fixed forcing/viscosity, скрытые высокие modes пересэмплируются из заданного закона. Цель — состояние в фиксированный момент. Это даёт conditional Monte Carlo teacher. Но PDE solver, cutoff, горизонт и число скрытых реализаций требуют отдельного convergence-пакета до научного запуска. Не использовать один детерминированный rollout на условие как «истинную дисперсию». Этот extension не разрешён текущим пакетом.

**Дистилляция.** Только если inference-randomization дорог из-за condition encoder или нужен один канонический sampler. Обучающий teacher — смесь распределений: fresh K и полный teacher-trajectory. Не усреднять velocities. Student condition=C, objective CFM по сэмплам teacher, оценка MMD-ошибки ε отдельно; A2 ограничивает потерю выигрыша. Нельзя подставлять training CFM-loss в ε без дополнительной оценки.

**Не запускать одновременно всё.** Решение выбирает один следующий пробел в доказательной цепочке. Количество датасетов не заменяет независимость, правильную метрику и установленную научную новизну.
